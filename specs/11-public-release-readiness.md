## 1. Scope & Purpose

Prepare the repository for publishing on GitHub:

1. **Remove every reference to the author's real mail data:**
   - archive names, employers and organisations
   - colleagues' names and email addresses, folder names, attachment names and subjects
   - home-directory paths, and statistics that identify a specific archive
2. **Replace that data with a fictional demo archive** that anyone can generate and open, and use it for the docs, the tests and the CLI defaults.
3. **Add three mock screenshots** to the README, captured from the demo archive only.
4. **Uplift the codebase and docs** to the standard expected of a public project: licence, contribution and security notes, CI, accurate package metadata, and no hard-coded personal defaults.

### 1.1. Definitions

| Term | Definition |
|---|---|
| **Personal data** | Anything derived from the author's real archives or machine. This covers: organisation, product and team names; people's names and email addresses; archive file names; folder paths; subjects; attachment file names; message text; home and mount paths; usernames; and per-archive statistics quoted alongside any of these. |
| **Denylist** | A local, **untracked** file (`.privacy-denylist`, one term or regex per line) holding the concrete personal terms. It is never committed, because committing it would itself publish the terms. |
| **Generic checks** | Privacy checks that need no denylist and therefore run in CI. They flag `/home/<name>/` and `/Users/<name>/` paths, email addresses outside reserved domains (`example.com`, `example.org`, `*.test`, `*.invalid`), and `.pst`, `.ost`, `.mbox` or `.eml` files committed anywhere except the demo fixtures. |
| **Demo archive** | Fictional MBOX and EML mail for an invented company, generated by a script. All addresses use reserved domains (RFC 2606). |
| **Mock screenshot** | A PNG of the real UI rendering the demo archive. It contains no personal data. |

## 2. Privacy Scrub

### 2.1. Text Replacements

Each real example is replaced with a fictional equivalent from the demo archive (§3), keeping the point the example makes. For example, "a 13 MB zip of training slides is the largest find" becomes the same claim about a demo file. Rules:

- **Specs 00–09:** keep the design content and rewrite the examples, mock-ups, sample JSON and measured tables with demo data. Measured performance figures stay, but are described generically ("a 415 MB, 4,101-message PST indexes in about 5 s"), with no archive name.
- **README and `architecture.md`:** the "sample archive" section becomes a "try it with the demo archive" section.
- **SVG diagrams:** edit the two affected captions.
- **`index.html` placeholder:** becomes `e.g. Alex, Priya`.
- **`AI-TOOL-EXECUTION-GUIDE.md`:**
  - **(recommended)** generalise the "never modify the archive" rule to "any archive under `data/`"
  - or move the guide out of the public tree

### 2.2. Code Defaults

- Delete `DEFAULT_PST_PATH`.
- `serve` without a path starts with **no archive open** and shows the File Browser, which Spec 08 already supports. `stats`, `index` and `export` require a path.
- `api.create_app(pst_path=…)` loses the personal default, and parameters named `pst_path` become `archive_path`, matching the multi-format reality since Spec 07.

### 2.3. Git History

The repository has one commit and has never been pushed, so scrubbing the working tree is not enough: the old blob would still be published.

- **Recommended:** after the scrub, replace the history with a fresh root commit (`git checkout --orphan`, commit, delete the old branch, then `git reflog expire` and `git gc --prune=now`). Nothing external refers to the old commit.
- Alternative: `git filter-repo`, which only makes sense if history is worth keeping.
- **Before the first push**, verify that `git log --all -p | privacy_check --stdin` returns zero hits.

### 2.4. Guarding Against Regressions

`scripts/privacy_check.py`:
- **Generic checks** (§1.1) always run.
- **Denylist checks** run when `.privacy-denylist` exists; it is added to `.gitignore`.
- Exits non-zero with `file:line` for every hit.
- Can scan the working tree, staged files (`--staged`) or stdin.
- Wiring:
  - an optional local pre-commit hook (`scripts/install-hooks.sh`)
  - a CI job that runs the generic checks
  - a test (`tests/test_privacy.py`) that runs the generic checks over tracked files

## 3. Demo Archive

`scripts/make_demo_archive.py [--out data/demo] [--seed 7]` produces fictional mail for an invented company, **"Larkspur Instruments"**, about 2001–2006.

| Output | Content |
|---|---|
| `larkspur.mbox` | About 400 messages across 6 people, spread over 5 years |
| `larkspur-eml/` | The same company's "Projects" mail as an EML folder tree with 3 levels of subfolders |

The content is chosen so every feature has something to show:

| Feature | Demo content |
|---|---|
| Threads (Spec 10) | Real `Message-ID`, `In-Reply-To` and `References` chains of 2–25 messages; one 40-message thread; unrelated messages that share a generic subject ("Update") |
| Attachments (Spec 09) | Generated PDFs, CSVs, a small zip containing documents, PNG charts, repeated signature logos and spacer GIFs (noise), duplicate forwards, one unnamed attachment |
| Search | Distinctive terms ("calibration", "Saltmarsh rig") |
| Inspector | The MBOX and EML formats; a checksum |

Requirements:
- The output is **deterministic** for a given seed, standard library only.
- It is **generated at test time and never committed**, apart from a tiny checked-in fixture if the generator proves too slow.
- Everything is fictional. All addresses use `@larkspur.example`, and names come from a built-in list of invented names.
- **PST:** no library can write PST files. PST-specific tests therefore become opt-in via `EAE_TEST_PST=/path/to/file.pst`, and are reported as skipped with that reason.

## 7. Acceptance Criteria

1. `privacy_check.py` with the full local denylist reports **0 hits** across:
   - the working tree
   - `git log --all -p`
   - commit messages and author fields (subject to the identity decision in §9)
   - the text content of every image, including SVG `<text>`
2. On a fresh clone with no `data/` contents, `uv run pytest` passes. **At least 90% of tests run** rather than skip, and the skipped tests name `EAE_TEST_PST` as the reason.
3. `uv run python scripts/make_demo_archive.py && uv run email-archive serve data/demo/larkspur.mbox` works end to end. The demo exercises threads, attachments (with noise and duplicates), search and the Inspector.
4. Three screenshots exist and are ≤ 400 KB each. They show only demo data (verified by eye and by the capture script's demo-only guard), and they render on the GitHub README.
5. CI is green on Python 3.11 and 3.12, and `ruff check` is clean.
6. Running `serve` with no arguments opens to the File Browser; no personal path remains in the code.
7. The final history contains no commit with personal data, verified before any `git push`.

## 8. Risks

| Risk | Mitigation |
|---|---|
| Personal data in places a text search misses (binary fixtures, image pixels) | No binary fixtures are committed. Screenshots come only from the demo archive, guarded by the capture script. SVG text is included in the scan. |
| The denylist leaks if committed | Add it to `.gitignore` before it is created; `privacy_check` refuses to scan if the denylist itself is tracked |
| Fictional names collide with real people or companies | Use an obviously invented company on reserved `.example` domains, with common first names and invented surnames |
| libpff wheels unavailable on CI's Python | Pin a working Python version; fall back to building from source in CI |
| A history rewrite after a push would break clones | Rewrite before the first push (it hasn't happened yet) |

## 9. Decisions Needed Before Implementation

1. **Git history:** **replace it with a fresh root commit (recommended)**, or keep it and rewrite it with filter-repo.
2. **Commit author identity on GitHub:**
   - your GitHub `noreply` address **(recommended for a public repo)**
   - or keep the current personal address
3. **Licence:** **MIT (recommended)**, Apache-2.0 or GPL-3.0. The only notable runtime dependency is `libpff-python`, which is LGPL-3.0+ and dynamically linked, so it is compatible with any of these.
4. **Specs folder:** **publish it scrubbed (recommended)**, or remove it from the public tree.
5. **`AI-TOOL-EXECUTION-GUIDE.md`:** **generalise it and keep it (recommended)**, or remove it.
6. **Demo company and theme:** "Larkspur Instruments", early-2000s engineering firm **(recommended)**, or another theme you prefer.
7. **Repository name and GitHub owner**, for the `pyproject` URLs and README badges.
